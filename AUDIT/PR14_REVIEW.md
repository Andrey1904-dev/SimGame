## 3. Найденные проблемы

### 3.1. P0 — карта оставалась пустой: `QuarterUnityAdapter.Build` обнулял план — ✅ ИСПРАВЛЕНО

**Файл:** `City/UnityAdapter/QuarterUnityAdapter.cs`, строки 66-74 (`ClearBuilt`) и
**114-121** (`Build`).

```csharp
public void ClearBuilt()
{
    _plan = null;                    // ← строка 68
    ...
}

public GameObject Build(QuarterPlan plan, Transform parent)
{
    if (plan == null) throw new ArgumentNullException(nameof(plan));
    _plan = plan;                    // ← строка 117  (плана ещё нет в сцене)

    // Повторный Build: предыдущий квартал и его меши уничтожаются.
    ClearBuilt();                    // ← строка 120  ОБНУЛЯЕТ _plan
```

**Доказательство (исполняемое):**
```
После Build(): HasPlan = False (ожидалось True)     exit code: 1
```
(модель с точным порядком вызовов, `TEST_RESULTS.md` §4.1)

**Влияние.** `UiBootstrap.ResolveDistrict()` читает `districtSource as IQuarterPlanSource`
→ `source.Plan` → `null`. Если план не передан вручную через
`UiBootstrap.SetDistrictPlan(...)`, карта рисует пустую сетку и сообщает
«плана района нет»; маршруты не строятся вообще. Это ломает сценарии №1, №4, №5.

**Исправление (2 строки):**
```csharp
public GameObject Build(QuarterPlan plan, Transform parent)
{
    if (plan == null) throw new ArgumentNullException(nameof(plan));
    ClearBuilt();          // сначала очистить (обнулит старый план)
    _plan = plan;          // потом записать новый
```
и добавить тест: `Build(plan); Assert(HasPlan)` — в Unity EditMode, либо вынести
присвоение в метод, который вызывается после `ClearBuilt`.

**Оценка.** Это ровно тот класс дефектов, который стабы поймать не могут:
`QuarterUnityAdapter` не компилируется без Unity (осознанно исключён из проверок),
поэтому PR его не проверял вовсе. Отчёт PR #14 об этом предупреждал
(«`QuarterUnityAdapter` вне проверки без Unity»), но последствие не было
прослежено до «карта пустая».

**✅ Как исправлено в PR #14 (`786c7fc`):**
* логика хранения плана вынесена из MonoBehaviour в чистый
  `City/Quarter/QuarterPlanSlot.cs` — именно чтобы её можно было проверить без
  редактора (корень проблемы: непроверяемый код);
* `BeginBuild(plan)`: `Clear()` → `Plan = plan`; `Build()` вызывает
  `ClearBuilt()` → `_planSlot.BeginBuild(plan)`;
* 6 регрессионных тестов в `City/Tests/QuarterPlanSourceTests.cs` + сквозной
  тест UI «источник плана → данные карты»;
* доказано откатом: на исходном порядке падают 3 теста City и 1 UI.

### 3.1b. P0 (Unity) — asmdef `UI/Core` без ссылки на `City.Quarter` — ✅ ИСПРАВЛЕНО

`UI/Core/QuarterPlanAdapter.cs:18` делает `using LifeFromZero.City.Quarter;`,
а `UI/Core/LifeFromZero.UI.Core.asmdef` объявлял `"references": []`.
В Unity это `CS0246` и каскад ошибок по всему PR. Не ловилось, потому что все
проверки UI компилируют файлы в одну сборку и asmdef не читают.
Ссылка добавлена; написан статический чекер графа asmdef (`asmdef graph OK`).

### 3.2. P1 — мост доставки без хоста

`DeliveryServiceBridge` ищет `DeliveryServiceHost` (`UI/Runtime/DeliveryServiceHost.cs`)
— абстрактный класс. Наследника в репозитории **нет**, поэтому в сцене
`Connected == false`, телефон пишет «Система доставки не подключена».
Это честное поведение, но ТЗ №042 требовало «телефон взаимодействует с доставкой»;
фактически взаимодействие появится только после 1 класса от интегратора.

**Решение:** либо добавить в PR готовый пример `SampleDeliveryHost` (создаёт
`DeliveryService` с заказами из `QuarterPlan`), либо явно понизить требование в
отчёте. Сейчас в `REPORT_042.md` статус описан корректно, но в заголовке PR
«телефон подключён к системе доставки» звучит сильнее, чем есть.

### 3.3. P1 — расхождение идентификаторов приложений телефона

| Источник | Заказы | Звонки | Задания |
|---|---|---|---|
| `Phone/Apps/PhoneAppRegistry.cs:55-59` (модуль) | `jobs` | — | — |
| `UI/Core/PhoneData.cs:19-30` (UI) | `orders` | `calls` | `tasks` |

Если подключить `PhoneFacade` (модуль) к экрану телефона, плитка «Заказы» не
найдётся по Id, а `jobs` не будет отрисована — экран покажет пустой набор.
**Решение:** один реестр Id (например, `PhoneAppIds` как единственный источник,
модуль приводит свои Id к нему).

### 3.4. P2 — `UiRouter` и `UiBootstrap` независимо перепривязываются к сцене

`UiRouter.OnSceneLoaded` вызывает `RebindSceneServices()`, `UiBootstrap.OnSceneLoaded`
— свой цикл `Resolve*` + `Configure`. Два независимых обработчика одного события
без гарантированного порядка. В худшем случае первые кадры после загрузки
сцены экраны работают со старыми (уничтоженными) ссылками.

**Решение:** оставить одного владельца перепривязки (`UiBootstrap`), а
`UiRouter.RebindSceneServices` вызывать только если бутстрапа нет.

### 3.5. P2 — `MapCanvasGraphic` и лимит вершин uGUI

Карта рисуется одним мешем через `VertexHelper`. Сетка 100 м на 750 м + 82 ребра
+ 70 точек ≈ 4 вершины на элемент. При `maxZoom = 3.2` число четырёхугольников
не растёт (толщина в пикселях), но `ushort`-индексы uGUI ограничены 65 535
вершинами. Сейчас запас ~10×, однако при добавлении зданий/маршрутов лимит близок.
**Решение:** разбивать на несколько `Graphic` по слоям (уже сделано для маршрута)
и зафиксировать тестом-оценкой количество вершин.

## 6. Вероятные проблемы реальной сборки Unity

Основано на чтении кода; **не проверено** (нет Unity):

1. `UI/Core` имеет `noEngineReferences: true`, но `UI/Tests/Console.csproj`
   подключает `City/Quarter/**` — в Unity это только Editor-asmdef, конфликта нет.
2. `UI/Runtime` ссылается на `UnityEngine.UI` — в Unity 6 UGUI поставляется
   пакетом `com.unity.ugui`; если пакет не установлен, сборка не соберётся.
3. `UiRouter` использует `#if ENABLE_INPUT_SYSTEM` и `#if ENABLE_LEGACY_INPUT_MANAGER`;
   при обоих выключенных клавиши не читаются (нужно звать `Request()` из проекта).
4. `UiInstaller` вызывает `SceneManager.MoveGameObjectToScene` и
   `EditorSceneManager.OpenScene(Additive)` — в сцене с `DontDestroyOnLoad`
   объектами это допустимо, но может оставить «пустой» корневой объект при
   повреждённой сцене.
5. Стабы `Camera.main`/`FindObjectsByType` возвращают `null`/пусто — логика
   на них не опирается (проверено), но в Unity `Camera.main` требует тега
   `MainCamera` на камере; если тега нет, `UiGameBridge` перейдёт к поиску любой
   камеры — правильный фолбэк.
