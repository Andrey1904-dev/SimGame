## 2. До любых изменений

1. Найдите существующий клон SimGame (`git rev-parse --show-toplevel`), получите ветку этого PR через `git fetch origin` / `gh pr checkout <номер PR №044>` в отдельном чистом клоне; после слияния — `origin/main`. Не делайте checkout поверх незакоммиченных правок. Проверьте `git status --short`, `git rev-parse HEAD`, `git log -1`, состояние PR и актуальность main. При незакоммиченных изменениях в любом репозитории сохраните их, не делайте reset/clean/stash без согласования.
2. Закройте Unity и убедитесь, что нет работающего экземпляра проекта (не удаляйте `Temp/UnityLockfile` вслепую). Убедитесь, что проект существует, прочитайте `ProjectSettings/ProjectVersion.txt`, проверьте доступность точного редактора и лицензию. Если версия другая — остановитесь, не запускайте миграцию.
3. Создайте **полную внешнюю копию** проекта, включая неотслеживаемые и игнорируемые файлы и `.meta` (одного Git-тега недостаточно). Проверьте свободное место и успешность `ditto`; сохраните путь копии вне проекта. Копия включает сцены, префабы, Packages, ProjectSettings, настройки и данные. Не продолжайте при неуспехе. Ниже команды запускать из корня клона SimGame:

```bash
P='/Users/homepc/Projects/LifeFromZero'
U='/Applications/Unity/Hub/Editor/6000.3.27f1/Unity.app/Contents/MacOS/Unity'
[ -d "$P/Assets" ] && [ -d "$P/Packages" ] && [ -d "$P/ProjectSettings" ] && [ -x "$U" ] || exit 1
cat "$P/ProjectSettings/ProjectVersion.txt"
B="${P}_backup_$(date -u +%Y%m%dT%H%M%SZ)"
[ ! -e "$B" ] && ditto "$P" "$B" || exit 1
printf 'Backup: %s\n' "$B"
git -C "$P" status --short  # если проект не Git — зафиксировать это в отчёте
```

4. Просмотрите пакеты и существующие модули: `find "$P/Assets" \( -name '*.asmdef' -o -name 'AdapterBridges.cs' -o -name 'UiBootstrap.cs' -o -name 'PauseController.cs' -o -name 'District750Link.cs' \) -print`. Дополнительно найдите по namespace и именам типов все существующие копии в Assets **и Packages**, включая отдельные файлы без asmdef, asmref и вложенные/родительские сборки. Установщик не обнаруживает все такие дубликаты, конфликтующие типы, GUID, symlink или чужие ресурсы автоматически. Проверьте `.meta` GUID на уникальность и ссылки; при совпадениях/неясной принадлежности остановитесь до записи. Прочитайте план: уже найденная asmdef может перенаправить установку в существующий каталог. Не разрешайте перезапись пользовательского кода.

## 3. Копирование кода: сначала dry-run

```bash
bash City/UnityIntegration/install_to_unity.sh "$P" --dry-run --with-domain-tests
# Только после изучения всего плана и отсутствия конфликтов:
bash City/UnityIntegration/install_to_unity.sh "$P" --apply --with-domain-tests
# Проверка повторного запуска: все установленные файлы должны быть SKIP
bash City/UnityIntegration/install_to_unity.sh "$P" --dry-run --with-domain-tests
```

Коды: 0 успех, 1 I/O/внутренняя ошибка, 2 аргументы, 3 неверный проект/открытый Editor, 4 исходники или python3, 5 конфликт/дубликат/нечитаемый asmdef. `--apply` сам повторяет dry-run; это не утверждение о полной атомарности или доказательство, что проект не изменился между проверкой и записью. Держите Editor закрытым и не допускайте параллельных изменений. Скопированы только `.cs`/`.asmdef`; существующие `.meta`, сцены, префабы, Packages и ProjectSettings этим shell-скриптом не заменяются. Конфликты блокируют запись. Не использовать `--overwrite` автоматически: изучить отличия, подтвердить принадлежность и получить согласие владельца; затем сначала `--dry-run --overwrite`, потом `--apply --overwrite` с теми же флагами. Перезаписываемые файлы и их `.meta` сохраняются в `LifeFromZeroIntegration/backups/`; частичная ошибка копирования требует восстановления из полного снимка. Пустые/частичные копии без якорей могут дать дубли — это ручной preflight, а не гарантия скрипта.

## 4. Реальный Unity и подключение

Откройте проект **точным редактором**, дождитесь импорта и компиляции, сохраните лог и устраните подтверждённые ошибки; Unity создаст новые `.meta` — не заменяйте старые GUID, сохраняйте новые `.meta` вместе с файлами. Проверьте `Console`, пакеты, и границы asmdef. При закрытом Editor доступна диагностическая команда:

```bash
"$U" -batchmode -quit -projectPath "$P" -executeMethod LifeFromZero.Setup.LifeFromZeroDiscovery.DetectBatch -logFile /tmp/lfz-discovery.log
```

Проверьте лог и отчёт в `LifeFromZeroIntegration/`, Build Settings и реальную сцену, не угадывайте стартовую. Если кандидатов несколько — выяснить по проекту/спросить владельца. `Tools → Life From Zero → Detect start scene` — та же диагностика; `Tools → Life From Zero → UI → Verify Scenes & Adapters (read-only)` проверяет связи, но пишет отчёт вне Assets.

**Запрещено автоматически создавать/перестраивать район**: `Tools → Life From Zero → Setup District750 & Pause` создаёт тестовую сцену; не запускать. `Integrate Into Game` может создать `Assets/_Project/Scenes/District750.unity`, изменить стартовую сцену и Build Settings. Не применять, если это создаст/заменит район или конфликтует с городом. В окне `Tools → Life From Zero → Integrate Into Game` сначала Dry-run; изучите все действия и блокеры. При отсутствии безопасного плана остановитесь и интегрируйте только подтверждённые необходимые связи с существующими объектами после полной копии, без генерации города. Для UI: `Tools → Life From Zero → UI → Check UI installation (dry run)`, затем только при безопасном плане `… → Install UI into game`. Убедитесь в отсутствии второго EventSystem/меню паузы/роутера ввода. Эти Editor-инструменты не принуждают к dry-run и не гарантируют охват всех конфликтов; копия обязательна. Сохраняйте только целевые сцены, не применяйте изменения префабов ко всем экземплярам без необходимости. Существующие пользовательские сцены и ассеты не перезаписывать импортом; изменения сцены через Editor допустимы только адресно после dry-run и копии.

При необходимости пакетный dry-run (Editor закрыт; `START` — проверенный путь `Assets/.../*.unity`):

```bash
"$U" -batchmode -quit -projectPath "$P" -executeMethod LifeFromZero.Setup.LifeFromZeroGameIntegration.IntegrateBatch -lfzStartScene "$START" -lfzDryRun -logFile /tmp/lfz-city-plan.log
"$U" -batchmode -quit -projectPath "$P" -executeMethod LifeFromZero.UI.Editor.UiInstaller.InstallBatch -lfzUiScene "$START" -lfzUiDryRun -logFile /tmp/lfz-ui-plan.log
```

Код выхода и содержимое логов/блокеры обязательны к проверке. Batch dry-run не эквивалентен проверке Play Mode. В привязке используйте существующие компоненты: `UI/CODEX_EXECUTE.md`, `CODEX_WIRING_MAP.md` и `UnityIntegrationKit/README.md` — справка, не команды для слепого выполнения. Реальные `UiWorldAdapter`, `UiSnapshotSource`, `IPhoneDataSource` зависят от проекта; отсутствующие источники не подменять фиктивными данными. Не обещайте durable финансовый журнал без реального сохранения.

## 5. Проверки и приёмка

В Unity Test Runner запустите доступные релевантные EditMode и PlayMode тесты City/UI и затронутых доменов; укажите имена, количество passed/failed/skipped, логи и причины пропусков, не запускайте все 508 без причины. Если невозможно выбрать релевантные тесты, объясните и спросите перед полным прогоном. `bash City/UnityIntegration/run_checks.sh --unity-project "$P" --unity "$U"` запускает все доступные тесты, поэтому не использовать по умолчанию; `--no-tests` запускает статические проверки и структуру, но **не** Unity. Его 0 при NOT RUN не является доказательством успеха. По окончании проверок проверьте Console на compile errors, Missing Script, исключения и ссылки.

В настоящем Editor/Play Mode на копии/с сохранённым состоянием проверьте: телефон открывается/закрывается и получает реальные данные; карта показывает существующий район и актуальное положение; HUD обновляется от настоящих источников; пауза/возобновление и Escape/P не дублируются и не блокируют движение неверно; доставка принимает/выполняет заказ и выплачивает ровно один раз на тестовых данных; переход квартира ↔ город возвращает в правильную точку и не плодит UI/EventSystem. Проверить Build Settings, реальные пути/имена сцен, положение игрока и отсутствие потерь состояния. Не исполняйте финансовые сценарии на ценных пользовательских сохранениях. При невозможности визуальной проверки отметить NOT RUN, не имитировать успех.

## 6. Откат и отчёт

При ошибке остановите работу и закройте Unity. Полный откат: сначала сохраните текущий проект в **другое** новое место для расследования, затем восстановите копию `B` в исходный путь, не удаляя её (например, после согласованного переименования текущего проекта: `ditto "$B" "$P"`). Проверить сцены, `.meta`, Packages и ProjectSettings и наличие незакоммиченных файлов. Частичный откат по встроенным бэкапам возможен только после анализа списка новых файлов и путей: нужно также удалить исключительно новые файлы и сгенерированные для них `.meta`, восстановить изменённые файлы и их исходные `.meta`, Build Settings; полная копия надёжнее. Не использовать `git reset --hard`/`clean` на пользовательском проекте.

В отчёте: актуальные SHA/PR, состояние Git до/после, путь и проверка копии, план и коды установщика, конкретные изменения, версия Unity/пакетов, лог компиляции, результаты тестов (включая NOT RUN), сценовые проверки, оставшиеся блокеры. Реальная компиляция, Play Mode, визуальное оформление и интеграция с данным проектом невозможны без локального Unity; встроенные проверки вне движка этого не доказывают.
