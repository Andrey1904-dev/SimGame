# Финансовые идентификаторы операций (ТЗ №021)

Один журнал кошелька обслуживает три системы, поэтому их идентификаторы операций
разделены по префиксам. Префикс — часть контракта: по нему адаптер кошелька (и человек
при разборе сохранения) понимает, что это за деньги.

| Система | Префикс | Пример | Собирается в |
|---|---|---|---|
| Economy — списание за покупку | `shop:` | `shop:buy-0007` | `FinancialOperationId.ForPurchase` |
| Economy — возврат за покупку | `shop-refund:` | `shop-refund:buy-0007` | `FinancialOperationId.ForRefund` |
| Delivery — выплата курьеру | `delivery:` | `delivery:order-12#3` | `PayoutOperation.ForOrder` |
| Debts — платёж по долгу | `debt:` | `debt:pay-0042` | `DebtPaymentId.ForPayment` |

Правила:

1. **Идентификатор операции уникален внутри линии сохранения (save lineage).** Повтор
   операции с тем же идентификатором и той же суммой обязан быть идемпотентным: деньги
   не двигаются, ответ повторяет прежний исход.
2. **Тот же идентификатор с другой суммой — конфликт** (`false`, ничего не начислено).
3. **Возврат/компенсация всегда выводится из идентификатора исходной операции.** У Economy
   это `shop-refund:<purchaseId>` при списании `shop:<purchaseId>`. Поэтому повторная
   компенсация не может получить новый ключ и «вернуть» деньги второй раз.
4. **Между линиями сохранения** (новая игра) адаптер кошелька обязан изолировать ключи:
   например, добавить собственный префикс линии (`save-3/shop:buy-1`). Модули этого не
   делают — они не знают, одна ли это игра.
5. **Никогда не переиспользуйте идентификатор для другой операции.** Delivery раньше
   склеивал `"delivery:" + orderId`; заново зарегистрированный заказ с тем же Id получал
   тот же ключ и не оплачивался. Теперь номер операции входит в идентификатор.

## Кто и что обязан реализовать

| Компонент | Обязанность |
|---|---|
| `MoneyWallet` (Unity) через `IIdempotentWalletAdapter` | Журнал `operationId → (вид, сумма, исход)`; долговечный, атомарный; `TryGetOperationState` отвечает по журналу |
| `FoodInventory` (Unity) через `IIdempotentInventoryAdapter` | Журнал выдачи `operationId → выдано/отклонено`; повтор не добавляет товар |
| Delivery `IIdempotentPayoutAdapter` | `TryCredit(operationId, rubles)` + `WasCredited(operationId, out bool)` |
| Debts `IDebtWalletAdapter` | `TryDebit/TryRefund/TryWasDebited` по `paymentId` (контракт уже был) |

Без журналов в реальных компонентах работают только гарантии одной сессии
(«Режим A», см. `ECONOMY_INTEGRATION_QUICKSTART.md`).
