# ТЗ #035 — подключение District750 и паузы

Среда этого репозитория не содержит Unity-проекта, редактора или C# SDK. Код и тесты Unity здесь **не компилировались и не запускались**; визуальное соответствие и производительность не измерены. Два предоставленных референса доступны в задании: `Pause Menu.PNG` — меню, `District750.PNG` — карта. Используйте эти изображения в Unity; они намеренно не включены в Git. В самом сообщении карта показана первой, несмотря на текстовую нумерацию.

## District750

Перенести точно `City/Quarter/` (включая `DistrictMap/` и asmdef), `City/UnityAdapter/` и весь набор `City/Tests/*.cs` и `City/Tests/City.Quarter.Tests.asmdef` с сохранением структуры. Не импортировать csproj в Assets. `QuarterPlan` и существующий `QuarterGenerator` сохраняются. `CityBootstrap` выбирает `DistrictMapGenerator` только при `Layout Id = district750`; по умолчанию остаётся `quarter250`. Тесты District750 зарегистрированы через `QuarterTestSuite` → `DistrictMapTests`; Unity-обёртка — `QuarterNUnitTests`.

В существующем проекте Unity 6000.3.27f1 создать новую пустую `DistrictTest.unity` в принятой папке сцен, не менять `CityTest` или Apartment67. Добавить корневой объект `City`, компонент `CityBootstrap`, выставить `Layout Id` **district750**, `Seed` **1904**, `Generate On Start` и `Add Colliders` включить. Для вида сверху: ортографическая камера в (375, 500, 375), поворот (90, 0, 0), size около 380, плюс освещение. Play: проверить отчёт и консоль. Игрок и спавн не подключаются автоматически: `PlayerHome` — данные, а не интерьер. Подробная проверка коллайдеров и доступности — `City/CODEX_UNITY_STEPS.md` §§ 6–8. `QuarterUnityAdapter` использует существующую внутреннюю палитру и кэш материалов, `MaterialFor`/`MaterialFromHex`, и `NeedsCollider`; инспектор `Add Colliders` управляет добавлением коллайдеров. Не настраивать новые материалы/меши на каждый объект. Старые документы могут содержать устаревшие указания изменить CityTest; приоритет у этого документа.

Python-зеркало (не исполнение C#): `python3 City/Tools/district_layout_check.py`. Ожидается 961 объект, 10 МКД (4/3/3), 5 частных домов, 24 точки, 46 доставок, 46 достижимых входов. АЗС-4: (85,395), южнее ломбарда (85,425); число АЗС — 4. Зеркало не доказывает визуальное соответствие C# в Unity. C# тесты при наличии .NET SDK 8: `dotnet build City/Tests/Console.csproj` и `dotnet run --project City/Tests/Console.csproj`. Unity Test Runner: EditMode `QuarterNUnitTests.RunAllQuarterTests`.

## Pause Menu — установка

Перенести `City/PauseMenu/` целиком вместе с asmdef, `City/PauseInputSystem/PauseKeyboardInput.cs` (вне любых asmdef, в Assembly-CSharp) и `City/PauseTests/` с asmdef. Нужны штатные Unity UI (uGUI) и Unity Test Framework для тестов; Input System — только если он уже используется в проекте. Не добавлять новый UI framework или менять активный input backend ради меню. Настоящих проектов и доступных компонентов вне этого репозитория мы не видим, поэтому автоматическая привязка к Economy, Phone и т. п. **не заявлена**.

1. Создать в стартовой игровой сцене отдельный **корневой** объект `Pause` с `PauseController`. Он создаёт один Canvas при Awake, сохраняется через `DontDestroyOnLoad`, не пересоздаёт UI при Esc и уничтожает дубликаты целого объекта при смене сцены. Не добавлять на этот объект другие жизненно важные компоненты. Вставить один prefab в другие точки прямого старта сцен только если необходимо; дубликаты будут удалены. Удалить/не использовать его в главном меню, если там не требуется пауза.
2. Подключить реализацию `PauseIntegration` в поле Integration. **Без неё открыть меню нельзя**: это специально предотвращает незащищённое отключение персонажа/конфликт окон. По возможности реализовать адаптер существующего менеджера окон и управления: `CanOpenPause()` проверяет приоритет модальных окон, `AcquireGameplayLock()` возвращает `IDisposable`, сохраняющий и восстанавливающий прежнее состояние всех управляющих входов (null означает отказ). Не устанавливать `timeScale`/курсор внутри адаптера: ими владеет контроллер. Реальный менеджер паузы, если имеется, должен стать единственным владельцем состояния; согласовать с ним владение временем/курсором вместо параллельного управления. Вызовы адаптера выполняются на главном потоке Unity.
3. Только если менеджера нет, можно добавить `StandalonePauseIntegration` на корневой объект Pause, назначить его в Integration, перечислить **все** `Player Input Behaviours` и корни конкурирующих окон (`Competing Modal Roots`). Массив поведения не может быть пустым; не включать в него сам контроллер паузы или UI. Этот адаптер отключает конкретные компоненты и восстанавливает их исходные `enabled`; проверьте, что они действительно блокируют движение/камеру. Он не блокирует ввод неизвестных систем и не заменяет полноценный роутер окон.
4. Если в проекте есть маршрутизатор ввода, направить Esc в `PauseController.Instance.HandleEscape()` только когда он выбрал паузу (и закрытие только если поверх неё нет другого окна). Направить физическую клавишу P в `HandlePhoneKey()` только для меню паузы. Не подключать параллельно другой обработчик. В автономной конфигурации при отсутствии роутера добавить `PauseKeyboardInput` на тот же корневой объект и включить `Use Standalone Keyboard`; он по умолчанию выключен. Input System: `Keyboard.current.escapeKey` / `pKey`; legacy fallback: `KeyCode.Escape` / `KeyCode.P`. Телефон доступен кнопкой и P, если интеграция его предоставляет. Никаких новых назначений другим ссылкам нет. Внешний роутер отвечает за то, чтобы не вызвать телефон другим шорткатом этого модуля.
5. В источнике данных наследовать `PauseDataSource`, заполнить `PauseSnapshot` только существующими данными, подписать поле Data Source. Неизвестные значения — null/пусто; проценты — 0–100; до трёх целей. При изменениях вызывать `RaiseChanged()` на главном потоке; обновление также при открытии. На источниках без событий достаточно обновления при открытии. Примеров значений в рабочем режиме нет.
6. Для действий реализовать `IsAvailable` и `Execute` в интеграции; нет системы — вернуть false. Для автономного адаптера включать запись Binding только после назначения существующего persistent UnityEvent; иначе кнопка отключена. Сохранение, загрузка, настройки, управление, главное меню, телефон, инвентарь, карта и задания не реализованы фиктивно. Не добавлять новую систему сохранения. При выполнении ссылки меню сначала закрывается и возвращает управление. Существующие подписи клавиш остальных быстрых ссылок можно вернуть в `ShortcutLabel`; это только отображение, обработчики остаются у приложения. Выход вызывает `Application.Quit()` только по нажатию (в Editor не закрывает редактор).
7. При смене сцен или смене экземпляров сервисов вызвать `Configure(newIntegration, newDataSource)` из инфраструктуры новой сцены; метод сначала закрывает меню и освобождает прежнюю блокировку. Закрывать меню **до** уничтожения сцены с её зависимостями; `sceneLoaded` — дополнительная страховка. Не закреплять уничтожаемые scene-local ссылки как постоянные. Обработать отдельные окна и `timeScale` как часть существующего менеджера приложения.

UI — uGUI, CanvasScaler, один создаваемый экземпляр интерфейса, шрифт `LegacyRuntime.ttf`, генерируемый один раз спрайт скругления, обычные Unicode-иконки (доступность глифов зависит от платформенного шрифта). Существующий активный `EventSystem` используется повторно; если его нет, создаётся временный при открытии, с `InputSystemUIInputModule` или `StandaloneInputModule` по доступному backend. При закрытии временный удаляется. При асинхронной/аддитивной загрузке сцен с собственным EventSystem закрыть меню до загрузки, чтобы не допустить кратковременных дублей. Нужны реальные изображения шрифта/иконок или проектные ресурсы, если стандартный шрифт не содержит символы. Нет ресурсоёмкого blur. Фиксированный aspect-fit в экран; на узких/маленьких экранах текст может стать мелким — требуется проверка читаемости, 1920×1080 и 2560×1440 отдельно.

## Проверка меню в Unity

Unity Test Runner → PlayMode → `LifeFromZero.City.Pause.Tests`: состояние, Esc/continue, восстановление произвольного масштаба времени и курсора, блокировка/восстановление поведения, повторный UI, отсутствие данных и действий, phone dispatch, дубликат в другой сцене. Эти тесты подготовлены, **не запущены**. Отдельно проверить реальное физическое P с активной английской раскладкой, мышь, EventSystem, реальные приоритеты окон, загрузку реальных сцен и отключение/восстановление контроллера, runtime-привязки сервисов, разрешения, шрифты и соответствие предоставленному референсу. Код использует физическую P, не символ локальной раскладки; языковую раскладку ОС сам не проверяет. Снимки экрана и FPS допустимо оценивать только после реального Play Mode. В случае ошибки компиляции/интеграции — минимально исправить первую подтверждённую ошибку без переработки карты или существующих систем.
